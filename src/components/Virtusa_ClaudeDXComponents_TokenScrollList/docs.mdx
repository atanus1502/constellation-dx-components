# Token Scroll List

## Overview

An infinite-scroll list for third-party APIs that page with a **continuation token** (for example `nextIdentifier` / `startIdentifier`) instead of a page number or offset.

Constellation's built-in table paging only sends page numbers, and each request is stateless, so there is nowhere reliable on the server to keep "the last token". This widget keeps the token in the browser instead: every chunk is requested with the token returned by the previous response, and the data page stays a stateless, parameterized pass-through.

## When to use

- The source API returns a continuation token and a last-page flag, and cannot jump to an arbitrary page.
- The result set is too large to fetch in full up front.
- You need the list on a landing page (PAGE) or in a case's Utilities pane (CASE).

If the result set is small enough to fetch completely, a list data page that loops through all tokens on the server and a standard Constellation table is simpler.

## Pega setup

1. **Data class** with `Entries` (Page List of your record class), `NextIdentifier` (Text) and `IsLastPage` (True/False).
2. **Data page** `D_TransactionsChunk` — structure **Page**, parameters `startIdentifier`, `maxRecords` and any filters (`fromDate`, `toDate`). Source: your REST connector. Map the request from the parameters (send `startIdentifier` only when it is not empty) and map `header.nextIdentifier` → `.NextIdentifier`, `header.isLastPage` → `.IsLastPage`, `data.entries` → `.Entries` in the response data transform.
3. Because every token is a separate parameter value, each chunk is its own data page instance — nothing has to be persisted on the requestor, `pyWorkPage` or a data table. The widget also calls with `invalidateCache: true`.
4. Make sure the data page can be called through the DX API by your access group.

## Behaviour

- The first request sends an empty token. Each response's token is sent with the next request.
- Loading stops when the last-page flag is true, the token is empty, or the token did not change (guards against an infinite loop).
- On an error the token is kept, so **Try again** re-requests the same chunk.
- **Refresh** discards the chain and starts again from the first chunk. Responses from an abandoned chain are ignored.
- Sorting and filtering are not offered: a token chain can only be read forward in the order the API returns it. Filter through `additionalParams` instead.
